# Claude Design 依頼プロンプト ── セキュリティカオスマップ

`index.html` 第2章の図は暫定版です。狙いは「読ませる図」ではなく、**見た瞬間に量に圧倒される図**。到達すべき読後感は次の一文です。

> こんなにリスクがあるのか。自社ではハンドルしきれない。一旦PaaSに任せよう。

参考：業界カオスマップ（ロゴが敷き詰められた一覧図）の情報密度。ただしロゴではなく、**リスクの所在**を敷き詰めます。

---

## 前提

**読み手**：年商300億円以上の企業のCIO・CISO・リスク管理責任者。ただし2000億円以下の層には専門用語が通じない。**専門用語には必ず平易な補足を添えること。**

**掲載面**：LP（スマートフォン閲覧を含む）。駅広告からの流入を想定しており、**じっくり読む場面ではない。**

**避けるべき状態**：論文の図。説明を読まないと意味が取れない構成。

---

## 共通の制約

```
【出力形式】
- インラインSVG 1つ。ラスタ画像・外部ファイル・外部フォント読み込みは不可（配信先のCSPでブロックされます）
- viewBox を指定し、width="100%" height="auto" でスケールすること
- テキストは <text> で出力すること（パス化しない）
- <title> と <desc> を付けること

【配色】必ず CSS 変数を参照し、リテラルの色は使わないこと（ライト／ダーク両テーマに追従させるため）
  var(--ink)        本文テキスト      #0F1926 / dark #EAF0F7
  var(--ink-2)      副次テキスト      #33414F / dark #C2CFDD
  var(--muted)      補足テキスト      #5D6B7C / dark #93A3B5
  var(--faint)      注記テキスト      #8695A6 / dark #718295
  var(--surface)    面（箱の地）      #FFFFFF / dark #121C29
  var(--surface-2)  面（ラベルの地）  #EDF1F6 / dark #182434
  var(--rule)       罫線              #D3DBE5 / dark #2A3A4C
  var(--navy)       重要資産の塊      #0A2540 / dark #050D17
  var(--blue)       防御・接続        #0057B8 / dark #5EA8FF
  var(--blue-wash)  防御の淡い地      #E7EFF9 / dark #132538
  var(--crimson)    攻撃・侵入        #AE0F22 / dark #FF8290
  var(--crimson-wash) 侵入の淡い地    #FBEAEC / dark #2C1519
  var(--amber)      流出・警告        #8A5A00 / dark #E8B45C
  var(--amber-wash) 流出の淡い地      #FBF1DE / dark #2A2213
  ※ var(--navy) の塊の上に置く文字だけは、両テーマで濃紺のままのため #FFFFFF / #CFE0F0 等のリテラル可

【フォント】font-family には var(--f-body)。見出しのみ var(--f-display) 可

【意味の割り当て】色は装飾ではなく意味を持たせること
  赤（crimson）＝ 侵入口 ／ 濃紺（navy）＝ 重要資産 ／ 琥珀（amber）＝ 流出口 ／ 青（blue）＝ 防御

【トーン】厳格・平板。避けるもの：グラデーション、ドロップシャドウ、絵文字、
  アイコンイラスト、3D表現、アニメーション、角丸の多用
```

## プロンプト：セキュリティカオスマップ

```
金融機関向けLPに載せる「セキュリティカオスマップ」をインラインSVGで作成してください。
サイバーリスクがどこに、どれだけ存在するのかを1枚で見せることが目的です。
1つひとつを読ませる必要はありません。量が伝わることが最優先です。

■ 全体構成：左から右へ3ゾーン。ゾーン間は太い矢印でつなぐ

  ゾーン①「侵入口 ─ どこから入られるか」（赤系）
    3つのグループに、それぞれ小さなタイル（チップ）を敷き詰める

    グループA：委託先・取引先
      保守ベンダーのアカウント／運用委託先／グループ会社／再委託先／
      クラウド事業者／データセンター事業者／SIer／派遣・常駐者
      （補足：国内脅威ランキング2位。4年連続）

    グループB：従業員の端末
      なりすましメール／偽のログイン画面／Web会議の招待リンク／
      共有ファイルの通知／受け取ったファイルの実行／私物端末／
      持ち出しPC／パスワードの使い回し
      （補足：URLをクリックさせる手口が主流）

    グループC：外部に公開しているサーバー
      会員サイト／申込フォーム／法人向けEB／公開API／
      キャンペーンサイト／リモート接続の入口／古い検証環境／
      利用しているOSSライブラリ
      （補足：24時間365日、外から見られている）

  ゾーン②「感染拡大 ─ 入られた後どこへ向かうか」（濃紺の塊）
    上から下へ、段階が進むほど濃くなる3段構成にする

    段1：一般従業員のアカウント
    段2：情報システム部門のアカウント
    段3：特権ID（Tier 0）── AD・Entra ID／PIM・PAM
      （補足：ここを奪われた時点で、他のすべての対策が無効になる）

    この3段の右側に「重要資産（クラウンジュエル）」の塊を置く
      顧客情報（CRM）／取引・決済データ／人事・給与／設計・機密文書／
      仮想化基盤／バックアップ／認証基盤
      （補足：最も狙われるのは勘定系ではなく顧客情報）

    段1→段2→段3→重要資産 の順に矢印を引き、
    「1台の端末から、ここまで到達される」ことが見えるようにする

  ゾーン③「流出口 ─ 何を通じて外へ出るか」（琥珀系）
    タイルを敷き詰める
      HTTPS（暗号化され中身が見えない）／メール（SMTP・IMAP）／
      ファイル転送（FTP・SFTP）／DNS／クラウドストレージ／
      Webメール／チャットツール／USB・持ち出し媒体
      （補足：業務で使っている通信ほど、監視の網から外れる）

■ 密度について
  タイルは小さく、数を多く。ゾーン①で20枚以上、ゾーン③で8枚以上。
  「全部つぶすのは無理だ」と感じさせる密度にしてください。
  1枚ずつ読ませる必要はないため、タイル内の文字は小さくてかまいません。

■ 図の下に1本の帯を置く
  「侵入口・感染拡大・流出口。この3工程のどこかが空いていれば、
   他をいくら固めても届かない」

■ サイズ：横長。viewBox は幅1200前後、高さ700前後を目安（内容に応じて調整可）
■ スマートフォンでは横スクロールで見る前提。文字が潰れない最小サイズを守ること
```

## 差し替え手順

生成されたSVGを受け取ったら、以下をClaude Codeに渡してください。

```
SBOAI_LP_MUFG_MOC リポジトリの index.html の図版を差し替えてください。

<figure class="flowfig"> 〜 </figure> の中にある <svg> 〜 </svg> を、以下のSVGに丸ごと置き換える。
<figure> と <p class="flowfig__cap"> と <div class="flowfig__scroll"> は残すこと。
<p class="flowfig__cap"> の文言は「セキュリティカオスマップ ── 侵入口・感染拡大・流出口」に変更する。

（ここに生成されたSVGを貼り付け）

【差し替え後の確認】
1. 色がすべて var(--...) 参照になっていること（リテラルの色が残っていないか）
   ただし濃紺の塊の上に置く白系文字のリテラルは可
2. 外部リソースの読み込みが増えていないこと（Google Fonts以外は不可）
3. タグの閉じ忘れがないこと
4. ライト／ダーク両テーマで文字が背景に溶けていないこと
5. 横幅の狭い画面で、図が自身のコンテナ内で横スクロールし、
   ページ全体は横スクロールしないこと
   （.flowfig__scroll は overflow-x:auto。内側のsvgの min-width を図の実寸に合わせて調整すること）
```
