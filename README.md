# SBOAI_LP_MUFG_MOC

SB OAI Japan「Patching as a Service」向け、**業界別 AIサイバーセキュリティ・レポート**のモック。

LPおよびホワイトペーパー（ダウンロード資料）の構成検証用に作成した、単一HTMLのレポートです。**7業界版**を同一フォーマットで生成しています。

## 業界版

全7業界とも、侵入口の主役は**外部に露出したサーバーの既知脆弱性**（リスク01）。下表の「最大の隙間」は、そこに続く業界固有の経路（リスク02）を指す。

| ファイル | 業界 | 業界固有の隙間（リスク02） |
|---|---|---|
| `index.html` | メガバンク | 委託先・グループ会社の接続口 |
| `regionalbank.html` | 地方銀行 | 共同センター接続点の手前（行内基盤・営業店端末）と地場の委託先 |
| `power.html` | 電力会社 | IT／OT境界と保守・遠隔監視回線 |
| `chemical.html` | 化学メーカー | 取引網とつながる共通認証基盤（EDI・調達PF） |
| `aviation.html` | 航空会社 | 空港側の共用旅客処理基盤（CUTE・CUPPS） |
| `logistics.html` | 物流会社 | 委託先の接続口と、バックアップに届く権限 |
| `telecom.html` | 情報通信会社 | 全顧客が通るマルチテナント共通基盤 |
| `railway.html` | 鉄道会社 | 運転支援アプリ等の外部委託先サーバー（業務系でも保安系でもない領域） |
| `regionalbank.html` | 地方銀行 | 共同センター・委託先（※キーワード散布図を試行中） |

## ビルド

```bash
python3 build.py
```

`templates/` の共通章（第1章・第5章 PaaS・第4章）と、`build.py` 内の `INDUSTRIES` に定義した業界別データから、7ファイルを生成します。共通章の修正は `templates/` を、業界別の中身は `build.py` を編集してください。

## 内容

各ファイルは1ファイルで完結します（外部依存はGoogle Fontsのみ）。

| 章 | 内容 |
|---|---|
| SUMMARY | 本レポートの結論（3点） |
| 第1章［共通］ | フロンティアAIが変えたサイバーセキュリティの前提 |
| 第2章［業界個別］ | 侵入口・感染拡大・持ち出し口の3観点での構成図とリスクマッピング |
| 第2章 リスクマップ［地銀のみ］ | キーワードを散布図状に配置（縦=切迫度／横=統制の所在／文字の大きさ=影響）。`build.py` の `kmap` にデータを持つ |
| 第3章 | 6つのリスク詳細（なぜ顕在化したか／実際に起きたこと／講じるべき対策） |
| 第4章 | 診断対象の選定軸と進め方 |
| 第5章 | PaaS訴求・価格・データ取扱い・申込CTA |
| APPENDIX | 出典・注記 |

## 構成の出典

- レポートの型：`セキュリティレポートの構成メモ`（共通パート → 構成図上のリスクマッピング → リスクごとに3点セット → PaaS訴求＋申込ボタン）
- リスクの整理軸：セキュリティ専門家レビューを受け、アクセス経路／感染拡大と重要資産／イグレス（出口）の3観点に再構成
- 脅威の順位：IPA「情報セキュリティ10大脅威 2026」組織編
- サービス仕様・価格・免責：`[0727最新]PaaS_初回ご説明資料`

## 実装メモ

- 単一HTML。CSSは`:root`のトークンで管理し、ライト／ダーク両テーマに対応（`prefers-color-scheme`と`data-theme`の両方）
- 図版はインラインSVG。テーマトークンを参照するため両テーマで追従する
- リスクマップ（`keymap()`）は、キーワードごとの (x=統制の所在, y=切迫度, 文字サイズ=影響) からビルド時にラベル位置を決める。重なりは決定的な緩和処理で解消しており、データ位置からの移動は最小限に留めている。他業界でも `kmap` を定義すれば同じ図が出る
- CTAリンクはPaaS公式申込サイトへ接続

## 未確定事項

詳細は `docs/論点集.md`。特に注意を要するもの：

- **PaaSがライブラリ／SBOMまで診断できるか**：レビューで最も重い指摘。「ライブラリの中身は分からない」であれば訴求力が大きく落ちる。SBOAIへの確認が必要
- **SBOMは国内で法的義務ではない**：経産省の手引と国際ガイダンス共同署名まで。義務と表現しないこと
- **金融庁・日銀の要請（2026/5/22）**：内閣官房「サイバーセキュリティ2026」には記載がない。本文では日付・発出主体を伏せている。**一次ソースの確認が必要**
- **勘定系の実態**：COBOL前提の記述は誤りとして削除済み。MUFG案件チームへのヒアリングが必要
- **業界選定**：金融はメガバンクより地銀が有力との評価（論点集 C-1）。地銀版 `regionalbank.html` を追加済み。どちらを広告の受け皿（`index.html`）にするかは未決
- **地銀版の要確認事項**：共同センターの構成・参加行数、地銀の情報システム部門／セキュリティ専任の人員規模。本文では具体数値を書かず定性表現に留めている
- ビジュアルは、Claude Designでの作り込みを前提とした暫定版
